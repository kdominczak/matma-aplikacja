# Matma – aplikacja do matury z matematyki

Aplikacja mobilna do nauki: krótkie sesje, serie dni, opanowane działy i szacowany wynik na tle progu (bez XP, rankingu i odznak – decyzja z 2.11.2026).

## Stos
- Next.js 16 (App Router) + TypeScript + Tailwind CSS v4
- Capacitor 8 (Android/iOS) – pakuje folder `out/`
- KaTeX do wzorów – w treści pytań LaTeX w `$...$`, renderowany przez `src/components/ui/MathText.tsx`
- Backend: Supabase (`supabase/migrations`, klient `src/lib/supabase.ts`). Konto: e-mail + hasło (nowe konto: kod OTP potwierdza e-mail, potem obowiązkowe hasło; reset hasła = logowanie kodem i nowe hasło, bez linków) albo Google (natywnie `@capgo/capacitor-social-login`, w przeglądarce przekierowanie) – `src/lib/account.ts`, konfiguracja `docs/konto.md`. Hasło ustawione = `has_password` w `user_metadata`. Aplikacja nie zakłada już kont anonimowych (były dla rankingu i AI); starsze anonimowe dostają e-mail/Google przez dopięcie (to samo id). AI, ocena zdjęć i kody poleceń tylko z kontem: serwer odmawia kontom anonimowym (`require_full_account()`, błąd MA030 → funkcja `ai` 403 `account_required` → `AccountRequiredError` → `AccountGate` w UI) – migracja `20261109120000_ai_requires_account.sql`. Ranking usunięty z aplikacji i z bazy (migracja `20261111120000_drop_ranking.sql`: profile, nicki, `answers`, `mistakes`, `question_keys`, zdjęcia) – serwer nie zna już kluczy odpowiedzi. Kopia postępu (`user_progress`) i historia arkuszy (`exam_attempts`) – prywatne tabele z RLS, synchronizacja w `src/lib/cloud-sync.ts` (najpierw pobierz i scal przez `progress-merge.ts`, potem wysyłaj) – jedyna droga postępu i Pudełka porażek na serwer. Kopię postępu zapisuje wyłącznie `save_progress(dane, oczekiwany updated_at)` – przy konflikcie (MA020) pobierz, scal, ponów; nie dawaj klientowi INSERT/UPDATE na `user_progress`. Migracje wyłącznie przez CLI z historią (`npm run db:push:test`, potem `db:push:prod`; projekt testowy `hewatagpzhxhuoaqckih`, `docs/wdrozenie.md`) – nigdy przez SQL Editor; nowy plik = kolejny wolny numer (14 cyfr, bez powtórzeń – `tests/migration-names.test.ts`)
- Kod wspólny aplikacji i funkcji Deno: `supabase/functions/_shared/*.ts` (czysty TS, importy z rozszerzeniem `.ts` – stąd `allowImportingTsExtensions`)
- AI (korepetytor, wyjaśnienia, podpowiedzi): wyłącznie przez funkcję serwerową `supabase/functions/ai` (Deno – poza tsc/eslint) – klucz Groq tylko w sekretach Supabase, nigdy w aplikacji ani w `.env`. Klient `src/lib/ai.ts` wysyła tylko `purpose` (`tutor`/`explain`/`hint`/`grade`/`transcribe`) i dane – prompt systemowy, model i limit tokenów narzuca serwer: prompty czatu `supabase/functions/_shared/chat.ts` (aplikacja importuje stamtąd tylko typy; etykiety trybów w `src/lib/ai-prompts.ts`), oceny `_shared/grading.ts`, modele `_shared/models.ts`; zapytanie bez `purpose` → 400 `bad_purpose`. Błąd Groq → 502 `upstream` + zwrot wiadomości (`refund_ai_quota()`, tylko `service_role`); wyczerpany limit → `AiLimitError` (pokaż drogę do `/premium`, nie zwykły błąd). Załączniki w korepetytorze (`src/lib/attachments.ts`): zdjęcia → JPEG ≤1280 px, PDF → tekst przez pdf.js na urządzeniu (skany jako obrazy); wiadomość z obrazem idzie do `VISION_MODEL` (Groq: max 3 obrazy na zapytanie)

## Ważne ograniczenie
`next.config.ts` ma `output: "export"`. Aplikacja działa bez serwera, więc NIE używamy:
Server Actions, Route Handlers z Request, `cookies()`, `headers()`, proxy, redirects/rewrites,
dynamicznych tras bez `generateStaticParams`. Dane z backendu pobieramy po stronie klienta.
API przeglądarki (`window`, `localStorage`, `navigator`) tylko w handlerach lub `useEffect`.

## Komendy
- `npm run dev` – podgląd w przeglądarce (http://localhost:3000)
- `npm run build` – static export do `out/`
- `npm run lint`
- `npm test` – Vitest: logika, treść zadań (KaTeX, klucze, punktacja) i migracje Supabase w PGlite (`tests/db/`). Po zmianie zadań, migracji lub logiki postępu testy muszą przechodzić
- `npm run blueprint:coverage` – ile różnych arkuszy w układzie prawdziwej matury da się złożyć z puli i gdzie brakuje zadań
- `npm run mobile:sync` – build + kopiowanie do projektów natywnych
- `npm run android` – sync + otwarcie Android Studio
